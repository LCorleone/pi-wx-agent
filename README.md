# pi-wx-agent

把 [Pi](https://github.com/earendil-works/pi) 作为个人助理接到微信：扫码登录、一次性认领、家人邀请制、持久会话、原生自动压缩、图片/文件收发、文件记忆与夜间反思。基于进程内 SDK（`weixin-agent-sdk@0.5.0` + `@earendil-works/pi-coding-agent@1.3.0`），无需公网入站端口。

- **扫码登录**：首次交互式扫码，后续复用登录态。
- **一次性认领**：终端打印 `OWNER_CODE`，微信发送该码即认领唯一 owner 会话。
- **家人邀请制**：`/invite` 生成邀请码，家人发码即可加入。
- **持久会话**：登录态、owner、会话 UUID 落盘，重启按精确 ID 恢复。
- **原生自动压缩**：启用 Pi 原生 `compaction`，阈值/摘要由 Pi 管理。
- **两层文件记忆 + 写后校验**：`MEMORY.md` 索引 + `memory/<topic>.md` 详情，保存后核对。
- **夜间反思**：每日 `dream.hour` 整理会话记忆，结果不发微信。
- **图片/文件收发**：入站统一落 `media/`，出站用 `ATTACH:` 约定。
- **typing 反馈**：以微信输入状态指示器表达进度，不额外 ack。
- **跨会话转述推送（可选）**：owner 会话被其它 Pi 会话指挥产生的回复可转发到部署者微信（默认关闭）。
- **自省命令**：`/status` `/cost` `/context` `/compact` `/stop`。
- **多用户硬隔离**：会话/工作区/记忆/媒体按 conversationId 哈希分目录。

## 安全前提

**Pi 可以直接执行 shell、读写服务账号能访问的文件，不逐次弹权限确认。只认领自己的微信，只邀请信得过的家人，使用专用非 root 账号，不要授予 sudo。cwd 不是沙箱。** 克隆仓库不提供模型额度、API 密钥或微信账号；模型调用（含压缩、dream）可能收费。

## 快速开始

**环境**：Node.js **>=22.19.0**（依赖实际最低版本，推荐最新 Node 22 LTS）、npm，Linux 推荐用于 systemd；自有微信与 SDK 支持的扫码服务、可访问微信与模型服务的网络、可用的 Pi 模型/API 认证。只安装本地 npm 依赖，不依赖主机全局 Pi、不使用全局安装软链接。

在克隆后的项目目录，以今后运行服务的同一专用账号执行：

```sh
npm ci
npm run build
npm test
cp config.example.json config.json
```

### 1. 配置模型认证（必需）

运行本仓库安装的 Pi CLI：

```sh
./node_modules/.bin/pi
```

在 Pi 内 `/login` 登录支持的提供商或保存自己的 API key，`/model` 选择可用模型（Ctrl+S 保存默认），然后退出。也可通过提供商环境变量提供密钥（如 `ANTHROPIC_API_KEY`）；不要把密钥写进本项目配置、Git 或命令历史。systemd 不继承交互 shell 的环境变量，需单独配置受保护的 EnvironmentFile。

模型来源优先级：`config.model` 指定值 → Pi 默认 provider/model → 第一个可用模型。可在 `config.json` 显式固定：

```json
{
  "dataDir": "./data",
  "model": { "provider": "your-provider-id", "id": "your-model-id" },
  "dream": { "enabled": true, "hour": 3 }
}
```

填写 Pi `/model` 显示的真实 provider/id，不要原样使用占位符。自定义兼容端点配置在 Pi `models.json`，详见安装包 `docs/models.md`、`docs/providers.md`。启动会验证模型可用性，但不能保证凭据未过期、余额充足、端点可达；实际运行失败返回通用错误，不向微信转发原始异常。固定模型也用于恢复会话，修改它会改变后续使用的模型，不删除历史。

可选 `extensions` 字段：字符串数组，把列出的 Pi 扩展文件加载进桥接会话，只加载清单内文件（不再走 SDK 原生扩展发现）。路径必须是绝对路径且启动时已存在；相对路径被拒绝，路径缺失则启动报错。默认不配置即不加载任何扩展。扩展与桥接本身同权限运行（可注册新工具），只应添加完全信任的代码。扩展仅加载进部署者（owner）的会话：成员会话完全不加载这些扩展（不注册、不激活、不描述），其工作区提示亦不提及；owner 会话中这些工具会被激活并连同其描述写入会话系统提示，对模型可见。配套可选 `extensionFlags`（对象 `{标志名: 布尔或字符串}`，须先配置 `extensions`）为已加载扩展提供其通过标志读取的取值：同时写入运行时标志映射，并以 CLI 风格令牌追加到进程 argv（布尔真为 `--name`，字符串为 `--name=value`；布尔假仅走运行时映射），供在加载期扫描 argv 的扩展识别；未注册的标志名仅记录一条警告。

可选 `pushExternalReplies` 布尔字段（默认不配置即不推送）：开启后，owner 会话中**非本桥接发起**的回合（如部署者的其它 Pi 会话经控制类扩展指挥本会话）完成后，最终回复文本会经 `Bot.sendMessage` 转发到部署者微信；成员会话永不推送，桥接自身发起的回合（聊天、dream、压缩）也永不推送。推送剥离末尾的 MEMORY_SAVED/ATTACH 标记行（外部回合的 ATTACH 只剥标记、不附文件），剥离后为空则不推。微信侧 `context_token` 只被**部署者本人**的入站消息预热（Bot 按登录账号持有者的固定键读取，成员消息不会写入该键），约 24h 有效、每令牌约 10 条、超限静默丢弃；冷启动（部署者尚无入站消息）推送会失败并记一条日志；所有失败只记日志并吞掉，不影响聊天。

### 2. 扫码并认领

```sh
node dist/main.js start --config config.json
```

首次在交互终端自动请求扫码。终端显示 `OWNER_CODE=...` 后，在微信向 bot **只发送等号后的完整码**，收到「认领成功」后发送普通文字即可。只有这一个会话能调用 Pi；后续启动复用登录态和 owner，不再次扫码或开放认领。

- 认领码为 128-bit 随机值，**10 分钟有效、全局最多 5 条未授权消息尝试、只能用一次**；认领消息本身不进入 Pi。有效期、尝试次数、码的哈希落盘，重启不刷新预算、不重新打印原码。
- 过期/输错/遗失码：**先停服务**，运行 `node dist/main.js claim --config config.json` 生成新码，再立即 `start` 并认领。`claim` 无权更换已认领 owner；迁移 owner 请停服务、备份，用新 dataDir 完整重新初始化，而非在线改状态文件。任何人拿到有效码都可能抢先认领，终端与 journal 日志应仅管理员可见。
- 一个 dataDir **只允许一个进程**：不要同时启动前台和 systemd，不要运行中执行 claim/login；v1 没有跨进程锁。

### 3. 邀请家人（成员邀请制）

认领后 owner 可把 bot 开放给家人：

- **`/invite`（仅 owner）**：生成 128-bit 邀请码，**24 小时内有效、窗口内多人可用同一码**；再次 `/invite` 立即作废旧码。码只出现在微信回复里，状态只落盘哈希。
- **加入**：未授权会话在微信**原样发送该码**即成为成员并收到欢迎语（说明这是部署者的助理、用量由部署者承担）；邀请码不消耗，24h 窗口内多人可复用。owner 未认领前任何人无法经邀请码加入。
- **`/members`（仅 owner）**：按加入顺序列出成员序号与加入时间（不显示哈希），序号供 `/kick` 使用。
- **`/kick <序号>`（仅 owner）**：按序号移除成员，回复含其加入时间以便核对序号错位；被移除者下一条消息回到「未授权」，已排队消息也不会执行。owner 不在成员列表里，不可能被踢。**踢人同时作废当前邀请码**：被踢者聊天记录里的旧码最多还能用 24h，不轮换即可静默重新加入；未完成加入的家人需要新码，再次 `/invite` 生成。移除不是擦除——其工作区/记忆保留，重新邀请后原会话恢复。

**信任边界**：成员是你信任的家人——无沙箱，与 owner 同享 Pi 的 shell/文件能力；所有成员的模型用量（含 dream、压缩）都由部署者承担（`/cost` 本就按会话统计）。**硬隔离**：每个会话（含 owner）的对话、工作区、MEMORY 与媒体完全按 conversationId 哈希分目录，互不可见，也不存在任何跨会话记忆读取；踢人/邀请不影响其他人的会话。多用户设计细节见 [docs/DESIGN.md](docs/DESIGN.md)。

### 4. 明确重新登录

扫码过期（SDK errcode `-14`）或想换登录时，停服务后执行 `node dist/main.js login --config config.json`：先删除该 dataDir 下所有已存微信账号凭据，再扫码保存新登录，**不会更换 owner 或删除 Pi 历史**；扫码失败需重试，之后重新 `start`。未登录的非交互服务会清楚报错退出，不在后台无限等扫码。

## 命令速查

| 命令 | 谁可用 | 作用 |
| --- | --- | --- |
| 普通文字 / 图片 / 文件 / 语音 | 已授权（owner 与成员） | 聊天与媒体收发；进度以微信 typing 指示器表示 |
| `/status` | 已授权 | 会话/模型/上下文/dream/记忆索引 |
| `/cost` | 已授权 | 累计 token 与费用（含被压缩历史） |
| `/context` | 已授权 | 上下文占用 |
| `/compact [说明]` | 已授权 | 手动压缩，走 Pi 原生 `compact()` |
| `/stop` | 已授权 | 中止**自己会话**当前任务（受 SDK 串行限制） |
| `/clear` | 已授权 | 清空当前会话上下文（保留工作区与记忆；SDK 自带，鉴权由桥接执行） |
| `/help` | 已授权 | 命令速查；owner 额外列出管理命令，成员回复省略管理块 |
| `/invite` | 仅 owner | 生成/轮换邀请码（再次调用作废旧码） |
| `/members` | 仅 owner | 列出成员序号与加入时间 |
| `/kick <序号>` | 仅 owner | 移除成员；**同时作废当前邀请码** |

自省命令在桥接层拦截，鉴权与 chat/clear 相同，未授权不触发任何 Pi 调用；owner 与成员均可用，均只作用于自己的会话。因 SDK 串行派发消息，`/stop` 无法在一条 chat 尚未返回时插队中断它，只能中止自己会话的后台 dream 或（若将来并发派发）正在运行的 turn；**任何人都无法用 `/stop` 打断别人的任务**（会话按 conversationId 哈希隔离，中止目标永远是发送者自己的会话）。管理命令成员使用会被拒绝且不触发任何 Pi 调用。SDK 自带 `/echo`、`/toggle-debug`、`/clear` 仍在桥接之前处理（`/clear` 鉴权仍由本桥接执行，成员只能清自己的会话）。

## 工作原理（要点）

**串行与回复**：SDK 本身全局串行，本桥接再用同一 FIFO 边界串行化 chat/clear/dream。普通文字等待一次 Pi run 完成后发送一次回复，不流式刷屏；新消息等待上一个 run，而不是把 `followUp()` 入队误认为已得到回复。**进度反馈就是微信 typing 指示器**：SDK 在调用 agent 前发送并每 10 秒续期，覆盖 `agent.chat()` 全程，回复后在 finally 取消；因此无需额外 ack。本桥接**默认不推送**（不调用 `Bot.sendMessage()`）；唯一例外是可选开启的跨会话转述推送（见配置节）：仅限 owner 会话、仅限非本桥接发起的回合（详见 DESIGN「跨会话转述推送」）。若部署环境未取得 typing ticket，则不显示输入状态（SDK 行为）。

**会话与压缩**：会话 UUID 在首条 prompt 前作为 intent 落盘，Pi 按该 UUID 创建 JSONL；重启按精确 ID 恢复，绝不「续最近的会话」，已成功运行的映射找不到 JSONL 会拒绝恢复，需补齐备份或明确 `/clear`。`/clear` 鉴权后重置 session 映射并 dispose，保留工作目录、`MEMORY.md` 和历史 JSONL，下一条消息新建会话、重启也不会回到旧会话，**这不是隐私擦除**；SDK clear 回调是同步接口，先回复成功提示、实际清理在 FIFO 中完成，磁盘写失败会禁用当前桥接（需管理员处理后重启），不能把 SDK 提示当作磁盘事务成功证明。**自动压缩显式开启**：使用 Pi 原生 `compaction.enabled=true`，在 SDK 资源加载后施加，不修改全局设置，阈值/重试/摘要/JSONL 由 Pi 管理；压缩会丢失细节且需模型额度。每个授权 conversationId 的工作目录名为 SHA-256 哈希，不把用户 ID 拼进路径；owner 与成员都仅保存哈希，成员名册只存加入时间、不存任何可读身份。首次工作目录写入项目自有通用 `AGENTS.md`，不覆盖已有文件；Pi 原生加载 cwd、父目录及 Pi 全局 context 指令。

**媒体收发**：入站图片与文件/视频完全同路——原文件复制到该会话工作区 `media/`（只取 basename、重名加后缀，不拼接用户提供的路径），提示词标注工作区相对路径，模型按需读取；**任何媒体字节都不进入提示词**（不经 `PromptOptions.images`、无 base64、无 MIME 白名单与大小上限——SDK 自身已限制下载大小）。图片临时文件为 `.bin`，桥接以魔数嗅探（只读 16 字节头：PNG/JPEG/GIF/WEBP）决定副本扩展名，原名已有真实扩展名则保留、未知保持 `.bin`；SDK 不回填用户原始文件名（`fileName` 恒为空，副本名取自其临时文件、文件按 MIME 保留扩展名）。语音只透传转写文字（空则注记「转写不可用」），音频文件本身不进入 Pi（Pi 无音频输入）。复制失败（含源不可读）降级为文本注记，chat 不会失败、原始路径不进提示词。出站用 `ATTACH: <工作区相对路径>` 约定，按 **realpath** 校验必须落在工作区内且为已存在普通文件（拒绝 `../`、绝对路径、指向工作区外的符号链接、目录/缺失），失败只剥标记、记 `attach-rejected`、不附文件且文字不变，多条只取第一条（`attach-dropped`）；每条回复最多一个附件、不支持音频。**入站不做去重**：SDK 在派发前即持久化游标，崩溃只丢不重放（at-most-once），没有重投队列。细节见 DESIGN「媒体收发」。

**记忆**：`MEMORY.md` 是索引（每条一行，软上限约 150 行），详情写 `memory/<topic>.md` 按需读取；**索引超限只被检测和上报，不自动裁剪、也不阻止最新事实丢失**（`/status` 显示行数并在超限时标注，每次实际执行的 dream 后记录 `memory-index-over-cap` 诊断；不做硬上限或自动迁移）。`MEMORY.md` 由模型在决定需要保存时创建，不是代码强制提取，也不会把文件全文塞进每条消息。**写后校验（不假装成功）**：模型保存事实须在回复末尾输出 `MEMORY_SAVED: <原文>` 标记行，桥接在运行前后快照并核对，仅在标记原文存在且存储本轮确实变化时判为已写入；失败则记 `memory-write-unverified` 并附加「记忆保存未能确认」提示，dream 同样核对、失败不标记成功。用户以命令式明确要求记住但回复无标记也按未确认处理；若模型把标记行放在回复**中间**，该行会原样发给用户（不计为声明、也不被剥离）。记忆是提示词驱动、非保证：可能漏记、误记或写入失败，重要事实请检查文件并要求确认，不要发送凭据；清会话后记忆仍可读，要求忘记时检查文件，原始 JSONL/备份仍可能保留该事实。

**dream**：默认启用，`hour` 是**服务进程本地时区** 0–23（可设 `TZ` 或关闭 `dream.enabled`）。启动及每分钟检查：从上次成功反思后第一条未处理活动的下一次该小时开始到期（不按「今天是否聊天」筛选），凌晨可补做前一天、离线错过后补做，忙则下次检查、失败保留待处理状态；对闲置会话真正 `await prompt()`，只整理当前可见上下文与已有 MEMORY，**不能找回已压缩原文**，结果不发微信。运行标记（`lastDreamAttempt` / `lastDreamSuccess`）使漏跑可检测、重复跑幂等：无新活动不重复，已覆盖活动不重复处理，进程在标记写入前崩溃可能重复一次（非 exactly-once）。为避免每分钟重跑模型，**未验证失败**会退避到该次尝试后的下一个每日边界才重跑，`/status` 提示「上次 dream 验证未通过」；抛出/提供商错误则重置 attempt 标记并保留每分钟重试（不触发该提示，仅见于日志与「有待处理活动」行）。细节见 DESIGN「Dream 调度」。

**运行时兼容**：部分安装形态下 Pi 会把自带的新版 undici 装成全局 fetch，它拒绝微信 SDK 每请求手动设置的 `Content-Length` 头，导致登录后所有消息轮询失败；桥接在 Pi 会话工厂就位后剥掉该头（undici 自行重算）。升级 Pi 后若微信请求报 `invalid content-length`，先检查垫片（`main.ts`）是否仍在工厂创建之后、SDK 启动之前。细节见 DESIGN「运行时兼容」。

## 数据与备份

`dataDir` 相对 **config 文件所在目录**解析为绝对路径；主入口在动态导入微信 SDK 之前设置 `OPENCLAW_STATE_DIR`，覆盖环境中的旧值。默认：

```text
data/
├── openclaw-weixin/          # SDK 实际子树：账号索引、凭据、同步游标/context 等
├── state.json               # owner/认领哈希、成员名册/邀请哈希、精确 session ID、活动/反思/attempt 标记
└── conversations/<sha256>/  # 每个授权会话（owner 与各成员）各自一个目录，互不可见
    ├── AGENTS.md             # 项目通用记忆+媒体规则（已有文件不覆盖）
    ├── MEMORY.md             # 索引：每条一行（模型按需创建/维护）
    ├── memory/<topic>.md     # 详情：按需读取
    └── media/                # 入站媒体副本（图片/文件/视频统一；出站附件也可写在此）
```

**只备份 data 不完整！** 停服务后一起备份：

1. `config.json`、整个 dataDir；
2. 服务账号的 `~/.pi/agent/`，尤其 **`sessions/<encoded-absolute-cwd>/*.jsonl`**、`auth.json`、`models.json`、`settings.json` 以及需要的 context/扩展/资源；如设置 `PI_CODING_AGENT_DIR` 则备份该目录；
3. 受保护的 provider 环境配置、服务 unit 和运行账号/路径/时区配置。

Pi JSONL 仍在默认外部位置，不移动到 dataDir；文件包含原始聊天和工具输出，敏感程度不低于凭据。恢复保持相同服务账号、Pi agent 目录和 **dataDir 绝对路径**，否则 Pi 的 cwd 编码目录变化、精确 ID 查找可能失败；路径迁移需人工核对/迁移对应 session 子目录，先备份、不直接在线移动；更换主机后微信/OAuth 仍可能要求重新登录。备份应加密，不上传到公开仓库。默认 data/config、node_modules、dist、内部开发记录和 `.pi/subagents` 已忽略；**自定义 dataDir 或其他密钥文件需自己加入忽略规则或放仓库外**。新状态文件 mode 600、目录 700、入口 umask 077；不会修复所有旧文件权限。SDK 可能在系统临时目录 `weixin-agent/media/` 下载附件，需按自己的保留策略清理。

## systemd（示例，不自动安装）

先用专用非 root 用户完成上述模型认证、扫码和认领，Ctrl+C 停前台。编辑 `pi-wx-agent.service`：

- `User/Group` 改成专用用户，工作目录与 `--config` 指向实际位置；
- `ExecStart` 使用 **绝对 Node 路径且版本 >=22.19.0**（nvm 安装不一定在 `/usr/bin/node`，同时调整 PATH 给工具子进程）；
- HOME / 可选 `PI_CODING_AGENT_DIR` 必须与手动认证一致，并确保项目、dataDir、Pi session 目录可写；
- 如需 API key，使用仅管理员/服务账号可读的 EnvironmentFile，不要把密钥放 unit 或 Git；
- 示例 `NoNewPrivileges`、`PrivateTmp`、`ProtectSystem` 不是完整沙箱，可能限制某些工具操作，按实际需求评估，不应为了方便改成 root。

确认后才由管理员手动执行（本项目不会替你执行）：

```sh
sudo install -m 0644 pi-wx-agent.service /etc/systemd/system/pi-wx-agent.service
sudo systemctl daemon-reload
sudo systemctl enable --now pi-wx-agent
sudo journalctl -u pi-wx-agent -f
```

停止：`sudo systemctl stop pi-wx-agent`。SIGINT/SIGTERM 停定时器和微信轮询、abort Pi、dispose 会话；10 秒退出上限，systemd 15 秒停止超时覆盖残留子进程。不要在仍运行时复制状态或重新扫码。

## 限制与安全边界

- **仅支持上述受限的媒体通道**：入站媒体以工作区 `media/` 副本 + 路径注记供模型自行读取（媒体字节不进提示词；副本名来自 SDK 临时文件非用户原名；图片扩展名由魔数嗅探补充），语音只透传转写文字；出站附件仅限该会话工作区内真实路径（realpath 判定，含符号链接）、每回复一个、不支持音频。SDK 可能在鉴权**之前**下载媒体并记录消息/用户信息。
- SDK `/echo`、`/toggle-debug` 在桥接鉴权之前处理，不调用 Pi，不能承诺对陌生人完全静默；`/clear` 在桥接明确鉴权，未授权不会触碰 Pi。
- 成员与 owner 同样信任、同样无沙箱：家人可信是前提（部署者自行拍板），不是安全边界；真正的边界只有会话/工作区/记忆的按会话哈希隔离，以及未授权拒绝。被踢成员的数据不删除（非隐私擦除），只是失去访问权。
- Pi 本地全局指令、skills、设置按 SDK 原生发现（配置 `extensions` 后，扩展改为只加载清单内文件）；使用干净专用账号并审查这些内容。不提供远程权限弹窗、沙箱、向量数据库、媒体模型、多进程/多账号管理、主动提醒（可选跨会话转述推送只是转发已完成的外部回合回复，不是定时提醒）。
- **跨会话转述推送是尽力而为**：只转发 owner 会话外部触发回合的最终完成文本（中间工具调用段、错误/中止/截断不推），依赖微信 `context_token`（仅被部署者本人的入站消息预热、约 24h 过期、每令牌约 10 条），失败或超限即静默丢弃，仅记日志；推送失败或未开启均不影响聊天。
- **记忆校验仍是提示词驱动**：`MEMORY_SAVED` 标记可能被模型遗漏（此时按未确认提示，不假装成功）；校验只断言「标记原文在运行后存在、且记忆存储在本轮发生变化」，不证明内容正确、无重复或与用户本意一致；没有独立 LLM 提取或数据库。
- **既有工作区不自动迁移**：v1 工作区里已存在的 `AGENTS.md` 不会被覆盖；若要采用两层记忆与写后校验约定，需管理员手动把新模板复制进该工作区（日志会记录一条迁移提示）。
- 文本回复只取本轮新产生的成功 assistant 事件，拒绝错误/中止/截断或无输出的 run，不发送上次回复或 dream 文本；可选转述推送同样只取外部回合最终完成（stopReason=stop）的 assistant 文本，桥接自身回合（含 dream/压缩）期间的任何 assistant 事件都不会触发推送。
- SDK 长轮询断线重试；账号过期需人工 login。SDK 在派发给 agent 前就持久化同步游标：崩溃可能丢消息但不会重放（at-most-once），没有自建持久消息队列，也未做去重。
- 未授权输入不能调用 Pi，但 owner 发来的网页、文件、引用仍可有 prompt injection。模型/工具能读取服务用户的凭据并联网，哈希目录不是隔离措施；日记、JSONL、MEMORY、日志均应私有。
